# ADR-003: Invite code, seat token and session ownership
Status: Accepted
Date: 2026-11-18

## Context
The spec requires that a public join code must never be the credential that lets someone act as a player after joining. With no server, the host must issue and verify credentials itself.

## Decision
- **Invite code** — generated by the host at startup from the OS CSPRNG: 8 symbols of Crockford base32 (40 bits) shown as `K7QF-M2XA`. It admits exactly **one** peer to the single open seat and is **consumed** when that seat is filled. Afterwards it is useless.
- **Seat token** — 128-bit random, hex encoded, issued by the host privately to the joined peer in the `welcome` frame. Required for `resume` after a disconnect. Never displayed, never logged, never sent to anyone else. Held in memory only for the MVP (the peer can resume while its process lives; restarting the peer process forfeits the ability to resume — documented limitation).
- Comparison of codes/tokens is constant-time.
- **Brute force:** one handshake at a time, ≥1 s delay before replying to a wrong code/token, 5 s handshake deadline. 40 bits at ≤1 guess/s is infeasible within a game's lifetime.
- **Seat assignment:** host chooses its colour (`--color white|black|random`, default white); the peer gets the other seat. Seats never change during a game.
- **Takeover protection:** while a peer connection is live, a `resume` with the correct token replaces the old connection (the old socket is closed). This handles half-open TCP connections after Wi-Fi changes; only the token holder can do it.

## Consequences
- Joining needs address + code: `vesper join 192.168.1.20:4747 K7QF-M2XA` (or enter them in the Join form).
- Logs and screenshots redact the token; the invite code is shown only on the host's waiting screen.
